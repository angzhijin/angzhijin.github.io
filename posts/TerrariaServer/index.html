Terraria Server 搭建

发表于2021-11-24更新于2026-07-18阅读次数

在刚买了腾讯云服务器后，碰上了Terraria开启了创意工坊，就想着搭一个服务器捣鼓捣鼓。在成功部署完成后玩了一个小时，又没有再碰过。不久之后，服务器就因为环境问题重装了一遍。

2021年11月，Terraria 1.4.3版本与饥荒联动了，虽然说两个游戏我都没有去深入去玩，但接着这个契机，重新在腾讯云服务器上装一个也好，顺便也补上这篇博客。

吐槽一下，现在连服务器都有双十一大促了，甚至比学生优惠还便宜，吐了🤮

#下载服务端

  • 官网地址：Terraria

在官网的页脚中选中PC Dedicated Server 即可下载，上传到腾讯云服务器

此外，还有Terraria的工具箱 TShock，提供管理员系统、建筑保护、地标传送等功能。有想折腾的可以捣鼓看看，像我这种云玩家也不需要那么多的功能

#服务端部署配置

  1. 新建文件夹

  2. 将压缩包解压到/bin目录下sudo unzip terraria-server-143.zip /opt/terraria/bin/

    至于这三个子文件夹Linux, Mac, Windows有何区别我也不是很清楚。我的理解是部署在不同平台要到不同平台的子文件夹下启动，但配置文件serverconfig.txt又只能在Windows下找到

  3. 修改配置文件 vim /opt/terraria/bin/143/Windows/serverconfig.txt（建议复制一份到上级目录便于掉用，如/opt/terraria/bin/下）

    其中的示例配置是windows环境下的，如路径需要改成linux环境下，建议直接添加到文档下方而不是用来取消注释。

    下面是我添加的配置项

    各项的含义为

    • world：按路径载入一个世界并自动生成，如果路径存在则下面3个配置不会生效
    • autocreate：如果没有找到就自动生成，地图规模为（1小2中3大）
    • worldname：新建的世界名字
    • difficulty：难度（0旅行1经典2中核3硬核）
    • maxplayers：最大玩家数（1-255）
    • port：游戏端口（默认为7777）
    • password：设定密码
    • worldpath：存储地图的位置

    除此之外，还有一些其他的配置项：

    • seed：创造世界时使用的种子
    • language：服务器语言（en-US，zh-Hans等）

  4. 启动服务器

    这个加载过程视云服务器性能和世界大小需求有关

    加载完成进入Terraria后台，会显示运行情况，如要退出，可以输入exit，地图会自动保存并退出。

  5. 建议使用screen后台启动

#Link Start

进入游戏后，选择 多人模式 - 通过IP加入，依次选择角色，输入IP、端口、密码，就可以愉快的玩耍啦～

#启动优化

通过调用程序启动太麻烦了，可以写一个脚本更快速的启动

  1. 新建用户（非必需）

    为Terraria单独创立一个用户。如不新建，则启动账户为默认的root或ubuntu等。（本人未新建，因为尝试后没有自己原用户用着舒服）

  2. 新建脚本文件sudo vim /opt/terraria/bin/terraria_script.sh

  3. 编写脚本文件

    尝试了很多次，在我的默认账户下执行screen -AdmS ...一直无法成功，必须加上sudo以超级账户root启用才会生效。

    后来找到原因：由于涉及多个文件，权限问题比较复杂，启用客户端都需要用sudo，我改了好几个主要文件为777都无法解决。最后只能在新建screen后，再使用sudo启用Terraria客户端。这也是相对来说最简洁的解决方案了。

  4. 修改权限sudo chmod 744 /opt/terraria/bin/terraria_script.sh

  5. 使用

#自启动&定时保存

如果云服务器意外重启，可以避免Terraria没被启动

  1. 创建文件定义 terraria systemd服务 /etc/systemd/system/terraria.service（注意修改文件路径和用户）

  2. 保存退出

  3. 启用自启动systemctl enable terraria

  4. 设置定时保存

    1. 安装启动服务sudo apt install cron
    2. 编辑定时任务crontab -e，第一次启用需要选择编辑器
    3. 添加*/10 * * * * sh -x /opt/terraria/terra_script.sh save

#注意

-------------------2021/11/24：

玩家客户端的版本必须和服务器的版本一样，也就一两天，我把Terraria更新到了1.4.3.1，就连不上服务器了

目前更新版本后如何使用原世界还在折腾中。

-------------------2021/11/28：

版本更新后，将新版本的服务端压缩包重新解压到/opt/terraria/bin/下，同时需要将TerrariaServer.bin.x86_64的权限改为744，再次运行即可启动

找回了第一次搭建时的参考参考[3]进行配置+分析，重新梳理了一遍，其实遇到的大部分问题都是权限原因。

/opt这些目录下基本是属于root用户，参考中的都是设为744即文件所有者可以读写，而其他用户只读。而即使我将相关的一些文件如TerrariaServer.bin.x86_64, terra_script.sh, serverconfig.txt这些权限改为777，也依旧需要sudo进行启用。

所以在写脚本时，有两种解决方案：

  1. 用户名改成root，每次调用脚本时加上sudo；
  2. 不修改用户名，脚本中新建screen后加上sudo处理（本人采用这种）。
