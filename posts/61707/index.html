数据库备份与恢复

发表于2022-04-23|更新于2022-10-23|数据库
|字数总计:1.2k|阅读时长:4分钟|阅读量:

#basebackup

基本备份过程

  1. Issue the pg_start_backup command
  2. take a snapshot of database cluster with the archiving command you want to use
  3. Issue the pg_stop_backup command

#pg_start_backup

四个操作

  1. Force into the full-page write mode
  2. Switch to the current WAL segment file (version 8.4 or later)
  3. Do checkpoint（记录当前的位置，恢复时从此处开始）
  4. Create a backup_label file ——此文件创建于base目录的同一层，包含有关基本备份奔丧的基本信息，例如此检查点的位置

#pg_stop_backup

数据库在一致性状态下才能打开

五个操作

  1. 如果pg_start_backup强制更改了非整页写入模式，则将其重置为非整页写入模式
  2. 写一个备份结束的XLOG记录
  3. 切换WAL日志
  4. 创建备份历史文件 ——此文件包含备份标签文件的内容和执行pg_stop_backup的时间戳
  5. 删除备份标签文件——备份标签文件是从基本备份恢复所必需的，一旦复制，就不必在元素数据库集群中

备份时候很简单，恢复时候是很深

#baseback备份

两种方式

  1. 产生压缩的tar包，-Ft指定

    花费时间较长，但是节省空间。支持表空间文件存放在其他目录下

  2. 产生跟源文件一样的格式，及原样格式，-Fp指定

    备份快，但不节省空间。如果有表空间路径放在其他目录下，则备份失败

#Point-in-time Recovery

PITR过程几乎与正常恢复（实例恢复）过程相同

区别

  1. 从哪里读取WAL段/归档日志
    • 正常恢复模式——从$PGDATA$目录下的pg_wal子目录恢复
    • PITR mode —— 来自配置参数archive_command中设置的存档目录
  2. 从哪里读取检查点位置
    • 正常恢复模式——从pg_control文件
    • PITR模式——来自备份标签文件

恢复流程

  1. 为了找到重做点，PolarDB使用内部函数read-backup-label从备份标签文件中读取“检查点位置”的值
  2. PolarDB从recovery.conf中读取一些参数值
  3. PolarDB开始从重做点重放WAL数据，可以很容易从“检查点位置”的值中获取
  4. 恢复过程完成后，将在pg_xlog子目录中（版本10及以上为pg_wal）创建时间线历史文件
