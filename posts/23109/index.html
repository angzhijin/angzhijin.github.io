    当配置中心和项目配置文件都配置了相同的项，优先用配置中心的

  5. 进阶

    1. 命名空间

      用于进行租户力度的配置隔离。不同的命名空间下，可以存在相同的GroupId或DataId的配置。

      通过在服务的bootstrap.properties配置spring.cloud.nacos.config.namespace=<namespaceId>来切换不同的命名空间。

      常用场景一：不同环境下的配置区分隔离，如开发测试环境和生产环境的资源隔离

      常见场景二：微服务间相互隔离，每一个微服务创建并只加载自己的命名空间

    2. 配置集

      所有的配置的集合

    3. 配置集IDDataID

      类似于配置文件名

    4. 配置分组

      默认所有的配置都在DEFAULT_GROUP中

      通过在服务的bootstrap.properties配置spring.cloud.nacos.config.group=<groupName>来切换不同的分组。

每个微服务创建自己的命名空间，使用配置分组区分环境dev/test/prod

  1. 同时加载多个配置集

    1. 微服务任何配置信息，任何配置文件都可以放在配置中心中
    2. 只需要在bootsrap.properties中说明加载哪些即可

#Feign 声明式远程调用

Feign（fen第四声？）是一个声明式的HTTP客户端，目的是让远程调用更加简单。

Feign提供了HTTP请求的模板，通过编写简单的接口和插入注解，就可以定义后HTTP请求的参数、格式、地址等信息。

Feign整合了Ribbon（负载均衡）和Hystrix（服务熔断），可以让我们不再需要显示地使用这两个组件。

Spring CloudFeign在NetflixFeign的基础上扩展了对SpringMVC注解的支持，在其实现下，我们只需创建一个接口并用注解的方式来配置它，即可完成对服务提供方的接口绑定。

#Gateway 网关

网关作为流量的入口，常用功能包括路由转发、权限校验、限流控制等。

SpringCloud GateWay 作为SpringCloud推出的第二代网关框架，取代了Zuul网关。

网关提供API全托管服务，丰富的API管理功能，辅助企业管理大规模的API，以降低管理成本和安全风险，包括协议适配、协议转发、安全策略、防刷、流量、监控日志等功能。

  • Spring Cloud Gateway

#核心概念

  • 路由：由一个ID、一个目的URL、一组断言、一组Filter组成
  • 断言：Java8中的断言函数
  • 过滤器：标准的Spring WebFilter。

#使用

  1. 创建网关项目，引入网关依赖

  2. 编写网关配置文件

    • Spring Cloud Gateway Configuration

    注意：

    1. 各种Predicts 同时存在一个路由时，请求必须同时满足所有条件才被这个路由匹配
    2. 一个请求满足多个路由的谓词条件时，请求只会被收割成功匹配的路由转发
