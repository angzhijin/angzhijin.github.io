GaussDB-对象管理

发表于2026-07-31更新于2026-08-20阅读次数

DDL（Data Definition Language，数据定义语言），是用于定义或者修改数据库中如表、索引、视图等对象的语句。本篇主要围绕数据库对象及对应的DDL语句描述。

大部分的数据库对象分类基本相同，但设计上，不同的数据库之间还是存在区别的。由于高斯数据库的底层使用的是postgresql，索引对于PG系的数据库，本文基本上都适用。

#表空间

表空间用于管理数据库对象的存储位置，本质上是操作系统上的一个目录空间。不同表空间间的数据是物理隔离的。

  1. 表空间上可建立多个数据库（官方不建议）
  2. 当表空间所在磁盘的使用率达到90%时，数据库将被设置为只读模式，当磁盘使用率降到90%以下时，数据库将恢复到读写模式。
  3. 自带了两个表空间：pg_default和pg_global。
    1. 默认表空间pg_default：用来存储非共享系统表、用户表、用户表index、临时表、临时表index、内部临时表的默认表空间。对应存储目录为实例数据目录下的base目录。
    2. 共享表空间pg_global：用来存放共享系统表的表空间。对应存储目录为实例数据目录下的global目录。

#数据库

数据库是组织、存储和管理数据的仓库。

#dblink

dblink是用于本地数据库与远程数据库之间建立连接所使用的通道。

  1. DATABASE LINK为private时仅能被创建者访问，而当DATABASE LINK为public时则所有用户都能访问。
  2. DATABASE LINK特性只在A兼容版本下可以使用。
  3. DATABASE LINK连接的远端数据库仅支持503.1.0及之后版本。
  4. 用户需要保证本地和远端数据库的兼容性参数DBCOMPATIBILITY和guc参数behavior_compat_options、a_format_dev_version、a_format_version取值一致。
  5. 创建DATABASE LINK权限需要使用GRANT语法赋予，新建用户默认无权限，系统管理员拥有权限（DB级权限）。
  6. DATABASE LINK创建的时候不会去验证是否能连接成功，如果缺乏相关的关键字，可能会在使用时报错。
  7. host参数不要使用127.0.0.1和localhost，会出现连接失败的情况。
  8. 使用DATABASE LINK对远端表操作时，会在本地创建与远端对应的SCHEMA，若本地不存在该表的元数据信息，会将元数据信息写入本地系统表中，此时会使用7级锁保证写入的一致性，持续到事务结束放锁，删除DATABASE LINK时会将相应的元数据信息删除。
  9. 使用DATABASE LINK时在本地创建的表仅用于存储远端表的元数据信息，无法通过\d或pg_get_tabledef函数查询到表结构。
  10. 如果业务中有长事务首次使用DATABASE LINK操作远端对象，会持续持锁直到事务结束，其他首次使用DATABASE LINK的事务会被阻塞。可通过一条快速执行的语句先对要使用的远端对象做查询操作使其元数据落盘来规避这种情况，如 “select * from t1@dblink where 1=2;”。另外，远端表结构发生变化时本地要更新存储的元数据信息，也会有类似情况。
  11. 如果本地与远端字符集不同，可能会出现无法转换的报错，报错信息为远端返回报错。当本地数据库字符编码为GB18030_2022时，发送到远端会被转换为GB18030。因此，若本地数据库的字符集为GB18030_2022时，远程数据库字符集只能是GB18030或GB18030_2022。
  12. 在本地显示的与远端对应的SCHEMA时会使用USERNAME（私有DBLINK才有）#远端SCHEMA@DBLINK名作为SCHEMA名，名称长度上限为63。
  13. 使用DATABASE LINK时在本地创建的表仅用于存储远端表的元数据信息，无法通过\d或pg_get_tabledef函数查询到表结构。
  14. 如果业务中有长事务首次使用DATABASE LINK操作远端对象，会持续持锁直到事务结束，其他首次使用DATABASE LINK的事务会被阻塞。可通过一条快速执行的语句先对要使用的远端对象做查询操作使其元数据落盘来规避这种情况，如 “select * from t1@dblink where 1=2;”。另外，远端表结构发生变化时本地要更新存储的元数据信息，也会有类似情况。
  15. 不支持DATABASE LINK相关数据库对象的dump

#模式

模式（schema）是一组数据库对象的集合，也可称为命名空间（namespace）。不同的schema中是逻辑隔离的，不同schema中可以存在同名对象。

  1. 默认初始用户和系统管理员可以创建 Schema，其他用户需要具备数据库的 CREATE 权限才可以在该数据库中创建 Schema。
  2. 每个数据库都包含一个 pg_catalog Schema，它包含系统表和所有内置数据类型、函数、操作符。
  3. 只有系统管理员和初始化用户可以在 public 和 pg_catalog Schema 下创建普通函数、聚合函数、存储过程和同义词对象，只有初始化用户可以在 public 和 pg_catalog Schema 下创建操作符，其他用户即使赋予 public 和 pg_catalog 模式的 create 权限后也不可以创建上述五种对象。
  4. ==通过 CREATE USER 创建用户的同时，系统会在当前会话连接的数据库中为该用户创建一个同名的 SCHEMA。==
  5. 默认情况下，用户只能访问属于自己的 schema 中的数据库对象。
  6. 通过将模式的 CREATE 权限授予某用户，被授权用户就可以在此模式中创建对象。
  7. 注意默认情况下，所有角色都拥有在 public 模式上的 USAGE 权限，但是普通用户没有在 public 模式上的 CREATE 权限。
  8. pg_temp和pg_catalog始终会作为搜索路径顺序中的前两位，无论二者是否出现在search_path中，或者出现在search_path中的任何位置。

#表

表是数据库中用于存储数据对象及对象间关系的一种数据结构。

#分区表

分区表是把逻辑上的一张表根据某种方案分成几张物理块进行存储。

  • 范围分区表
  • 间隔分区表
  • 列表分区表
  • 哈希分区表

#索引

索引是数据库表中一列或多列值进行排序的结构。主要有以下几类索引：

  • 唯一索引
  • 多字段索引
  • 部分索引
  • 表达式索引（函数索引）

建议

  • 每个表不超过4个索引
  • 涉及分区数据变更的操作会使得Global索引失效，可以通过UPDATE GLOBAL INDEX子句来同步更新Global索引，包括删除（Drop）、交换（Exchange）、清空（Truncate）、分割（Split）、合并（Merge）这5种。

#视图

视图是一种逻辑表、虚拟表，不存储数据。数据库中只存储视图的定义，数据仍旧在原来的基本表中。

建议：

  • 不建议视图嵌套视图
  • 视图定义中避免排序，建议在调用时排序order by

#存储过程/函数

区别：

  • 函数是使用PL/SQL语言创建；存储过程是SQL、PL/SQL、JAVA语言的组合，禁止用于实现业务逻辑
  • 函数需要return 返回
  • 调用方式不同
  • 存储过程编译一次，函数每次重新编译

#角色

角色主要是用于管理权限，是一组用户的集合，相当于没有登录权限的用户

用户是用于登录的。
