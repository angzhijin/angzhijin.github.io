SpringBoot中日志输出

发表于2023-04-17|更新于2023-04-17|学习笔记
|字数总计:2.7k|阅读时长:11分钟|阅读量:

日志在项目运行与维护相当重要，是排查程序错误的重要依据。

之前做项目时候为了以防万一，加了日志功能，刚好就在后面排查bug的时候用上了，不愧是我～

#日志分级

以常见的logback日志分级为例，从严重到普通分为五个级别

  • ERROR：程序运行发生错误，可能导致系统崩溃的
  • WARN：警告，存在潜在错误
  • INFO：记录系统运行状态的信息
  • DEBUG：调试时的帮助信息
  • TRACE：粒度最小的日志

#SpringBoot Properties配置

SpringBoot默认加载Logback实现，spring-boot-starter-web依赖下引入的logging依赖就是使用的logback。

#Logback 配置

配置文件logback.xml/logback-spring.xml基本结构

#root

根记录器，配置全局的日志级别，可添加若干个日志节点

属性 说明
level （唯一，非必填）日志级别，可配置为TRACE、 DEBUG（默认）、INFO、WARN、 ERROR、ALL或OFF之一，不区分大小写

元素：

  • appender-ref：引用appender

#logger

配置记录器，可配置任意数量

属性 说明
name 名称
level 日志级别，可配置为TRACE、 DEBUG（默认）、INFO、WARN、 ERROR、ALL、OFF或INHERTED（NULL）之一，不区分大小写。对于未配置的将继承上一层的日志级别，直到<root>级
additivity 可加性，为避免重复打印，一般设置additivity=false，控制logger不再发送给更高层的appender。

元素：

  • appender-ref：引用appender

#appender

属性 说明
name 节点名称
class 需要实例化的appender类，常见有ConsoleAppender、FileAppender、 RollingFileAppender
  • ConsoleAppender：输出到控制台
  • FileAppender：输出到文件
  • RollingFileAppender：滚动方式输出到文件（类似于归档），在FileAppender的基础上达到特定条件自动切换记录目标为下一个文件。
基本元素 说明
<layout>
<encoder> 编码器，将事件转换为直接数组，写入到输出流中
<filter> 常见有PatterLayoutEncodr，输出日期、级别、线程、记录器名称、文件名、行号、消息等内容过滤器
<ImmediateFlush> 立即刷新到输出流，默认为true，为提高日志吞吐量，可设为false

#FileAppender

独有元素 说明
file 输出文件

#RollingFileAppender

独有元素 说明
<rollingPolicy> 滚动策略
<triggeringPolicy> 滚动触发条件
<pruduct>

  • rollingPolicy

    • TimeBasedRollingPolicy：基于时间的滚动，按时间切换不同的文件，同时也是Triggering Policy。

      • fileNamePattern：已滚动（归档）的日志文件命名格式

        以${log.path}/${server.name}/log-info.%d{yyyyMMdd}.%i.log.gz为例，%d{yyyyMMdd}表示日期，可添加时区为%d{yyyyMMdd,UTC}；%i表示日志文件的递增索引，从0开始；以.gz/.zip结尾表示启用自动压缩。

        如果配置了file属性，当前使用的日志文件以file命名，为配置则按fileNamePattern进行命名

      • maxHistory：日志文件保留天数

      • totalSizeCap：存档文件总大小的上限，超出后删除最旧的存档，默认为0

      • cleanHistoryOnStart：appender启动时删除存档

    • SizeAndTimeBasedRollingPolicy

      • 同上
      • maxFileSize：日志文件大小上限，超出后切换为下一个，文件名由%i区分。

  • triggeringPolicy

    • SizeBasedTriggeringPolicy
      • maxFileSize：唯一属性，默认10MB，

#SMTPAppender

将日志积累在缓冲区中，达到条件后通过SMTP发送电子邮件

#DBAppender

将日志添加到数据库表，分别为logging_event, logging_event_property, logging_event_exception，必须使用前便创建好。

支持SQL Server、Orcle、MySQL、PostgreSQL、SQLite等主流数据库。

#SiftAppender

根据给定的运行属性分离/筛选日志记录，如不同用户的日志文件。

#AsyncAppender

异步记录器，充当调度器，需要引用另一个appender才能起作用。

具备三个特点：

  1. 以事件损失为代价：AsyncAppender的队列满80%时会丢弃TRACE、DEBUG、INFO的事件。
  2. 应用启动/关闭时必须停止该Appender，以便停止并回收线程，并清除日志事件。
  3. 处理队列事件的线程可能中断导致队列中事件滞留。官方建议在JVM生命周期中插入钩子，在JVM关闭后正确停止Logger上下文。
元素 说明
<queueSize> 日志事件队列大小，默认256
<discardingThreshold> 默认情况下，队列满80%进行自动丢弃。设为0则保留所有事件
<includeCallerData> 提取调用方数据，默认false，只复制线程名、MDC等简单数据。
<maxFlushTime> Logger上下文停止时，超时处理的最大值，超过后丢弃队列中未处理的事件
<neverBlock> 默认false，阻止应用而不丢弃消息；true时丢弃消息而步组织应用

#encoder

属性 说明
class 目前，PstternLayoutEncoder是唯一有用的编码器。
要素 说明
<pattern> 日志格式
<outputPstternAsHeader> 在日志顶部插入日志格式

#layout

将传入事件转换为字符串输出，0.9.19前encoder的功能是有layout实现的。

属性 说明
class Layout的定义实现类，可以通过实现Layout接口或继承LayoutBase类进行自定义。使用最多的是Patternlayout.

由于FileAppender+Patternlayout的组合最为常见，所以定义了PatternLayoutEncoder进行了包装。

pattern的定义方法很多，这里举个常见的：

颜色属性可以为<appender>添加<withJansi>元素调用Jansi库解释ANSI颜色代码，并使用%white()/%boldYellow/%highlight()等对pattern中的输出元素进行包裹

#filter

日志过滤器，过滤出需要的日志事件进行记录，基于三元逻辑实现。

常规过滤器

  • LevelFilter：筛选低于日志级别配置的日志事件，同等级别由<onMatch>决定，更高级别由<onMisMatch>决定，默认都为ACCEPT。
  • ThresholdFilter：筛选日志级别低于配置的日志事件，低的会拒绝。
  • EvaluatorFilter：配置事件评估器EventEvaluator评估事件决定是否接受
    • <evaluator>：定义评估器
      • <expression>：使用表达式进行评估，要求返回的为boolean值
      • <matcher>：可复用的模式匹配器

#变量

变量定义，有property/variable/springProperty，使用${}进行变量引用

property与variable在logback 1.0.7 后相同，可互换使用（property本身xml就可以提供）

variable属性 说明
name 参数名称
value 参数值

springProperty可以与properties配置文件关联，但要求logback配置文件命名为loggback-spring.xml

springProperty属性 说明
scope 域，“context”
name 名称
source spring properties中的属性

#include

引入外部配置，外部配置需要由<included>嵌套

属性可以为file（文件绝对路径）、source（文件类路径）、url（网络资源）
