PostgreSQL进阶

发表于2022-04-22更新于2026-07-18阅读次数

报了个阿里云的 PolarDB For PostgreSQL 训练营，基于这个训练营顺便再进一步学了下PostgreSQL。

所以严格来说是参照PolarDB回顾PostgreSQL

这一节课主要讲的还是PolarDB/PG 与Oracle和MySQL 的一些对比上，不过被我当成是进一步理解PostgreSQL~~

#数据库、schema与用户

  • 用户：与权限一起，决定能不能做某样操作
  • schema：表的属从，逻辑上划分表
    • 表属于某个schema，表默认都属于public schema
    • 不同schema中的表，可以重名
    • 可以跨schema访问表
  • 数据库：物理上决定着表的存储位置。对应Oracle 12c之后的PDB
    • 不能直接夸数据库访问表，只能通过dblink形式跨库访问表
    • 不同数据表，可以有重名的schema
    • 每个数据库有自己的原数据，但共享xlog等公共资源

#数据库配置

  • pg_hba.conf：数据库网络配置
    • 远程登录管理
  • postgresql.cong：数据库配置
    • 端口
    • 监听地址等

#表空间

独立于数据库之外的概念，实例级别。

  • pg_tblspc：见下《实例与数据库》
  • 16396：space的OID
  • 13404：数据库的OID，test22表存储在postgres数据库中
  • 16397：表test22自身的OID

#对比

  • Oracle：

    一个表空间最多包括1024个数据文件

    Oracle在多个数据文件中做类似条带的I/O分批操作

  • MySQL / PG / PolarDB

    表空间是一个目录

#实例与数据库

  • Orcle：数据库实例与表空间没有关系。表空间中数据文件可以位于任何位置。实例级相关的数据，在ORACLE_HOME中。

  • PolarDB/PG：数据库实例对应一个固定的位置。initdb初始化一个数据库实例、以及在启动数据库实例时，都要指定一个位置：pg_ctl -D /data/pgdata3 start

    这个位置中有实例的各种配置文件，都是独立于数据库之外的（如postgres.conf）。

    实例的所有文件（包括所有数据库的所有文件），都要在“/data/pgdata3”目录中，但表空间可以在这个目录之外，违反了这个基本准则

    解决方案：

    /data/pgdata3/pg_tblspc中，放置一个指向表空间位置的软链接。

#用户权限体系

  • Oracle

    用户也是Shema

  • MySQL / PolarDB / PG

    用户、Shema分离

    用户作用：登陆数据库的凭证，和权限结合，控制客户端的操作
