excel内容匹配(pandas)及python打包为EXE

发表于2022-07-18更新于2026-07-18阅读次数

今天我哥那来了个需求，要在两张表里去匹配某一列数据在另一张表出现的位置，而这些数据可能是由多个编号拼接而成。

比如表一中有12345,98765,667788，要在表二中找出12345, 98765, 667788所在的行数，而且出现次数不确定，且表二中的也是拼接而成，如00000,12345。

原本打算依靠Excel去解决，但似乎不太行，我所接触的最强大的工具VLOOKUP也只是能找到匹配的第一个罢了。

于是乎，试着拿python去写了（研究生以来还是第一次写）。

#技术选型

  • Python
  • Pandas
  • pyinstaller

#需求实现

最开始，也只是想着读取每一行，将一行数据拆分为字符串数组，然后遍历这个数组，去表二每一行字符串中看有没有。

思路很简单，难的还是对python许久不写不太熟悉。

这个思路写完，发现效率拉的一批，毕竟三层循环的基础上还加了了很多低效查询。。。

#读取数据

第一步是读取excel数据，找了下有三四种方法，但最直接的还是使用pandas，相对来说也是稍微熟悉点的。

存储结构的话两个表都是|序号|数据|的格式

读取并转储为DataFrame格式

read_excel 有多个配置项，这里列一点

  • sheet_name: 可以是数字也可以是sheet的名字，数字的话对应顺序
  • keep_default_na: 对于空单元格读取为"", 而不是NaN

#数据匹配

按照笨办法拆分匹配效果太差，抱着试一试的心态搜了搜“pandas查找excel包含字符串的行”，居然真有！！

arr = sheet2.loc[(sheet2['数据2'].str.contains(ss))]

#数据导出

导出方法也很多，但为了便捷，我需要把它导出到同一个文件中，采用的是基于openpyxl引擎的读写

pd.ExcelWriter配置项：

  • mode: a==append, 表示附加模式，不另外新建文件；w==write，覆写
  • engine: 使用的引擎，还有一种是 xlsxwriter

sheet3.to_excel配置项：

  • sheet_name：导出到sheet表的名字
  • encoding：编码格式

补充：

由于需求之一是url地址的匹配，在数据量逐渐增大之后，出现了新的问题：

xlsxwriter\worksheet.py:1179: UserWarning: Ingoring URL 'xxxxx' since it exceeds Excel's limit of 65,530 URLS per worksheet，就是说excel的工作表中只能放65530个URL超链接格式文本。

解决方法就是配置strings_to_urls项，写出的时候url仅以文本格式写处，而不是写成url超链接格式。

注意此时无法写简写版了，因为to_excel函数不提供option参数。

#打包为可执行文件

毕竟不是谁都会给自己电脑安装python环境的，所以我打算打包成exe，之前也试过将冬奥时很火的python绘制冰墩墩打包成exe过。

主要依靠pyinstaller

常用的参数有：

  • -F, –onefile：覆盖打包
  • -w：使用windows子系统执行，程序启动时不会打开命令行
  • -c：带控制台，使用windows命令行执行（默认）
  • -i，-icon：指定打包后的图标

有一点不太友好的是，他会把当前环境中的所有的依赖库一起打包，不管程序是不是用到了。

一种方法是在它生成的一个xxx.spec中配置excludes=[]项排除不需要的包。

简单一点就是重新搞个环境，这一点使用conda就很方便了。

对于打包这一需求，其实golang挺好，编译完就会生成不同操作系统下的执行文件。

而pyinstaller就比较憨，只针对当前的系统进行打包，比如说Mac上打包成Unix可执行文件，Win上打包成EXE可执行文件。
