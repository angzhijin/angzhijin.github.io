页面管理

Font-matter

Front-matter 是 markdown 文件最上方以 — 分隔的区域，用于指定个别档案的变数。

未提示“必需” 均为可选项

Post

  • 文章页配置

  • 文章置顶

    从Hexo 2.0.0 开始支持文章置顶功能。

    在文章的font-matter中添加sticky: 1属性，数值越大，优先级越高

Page

  • 页面配置

标签页

  1. 新建tags页面 hexo new page tags
  2. 在/page/tags/index.md的Font-matter中添加 type: "tags"

分类页

  1. 新建categories页面 hexo new page categories
  2. 在/page/categories/index.md的Font-matter中添加 type: "categories"

友链页

  1. 新建link页面 hexo new page link

  2. 在 /page/link/index.md 的Fontmatter中添加 type: "link"

  3. 添加友链

    1. 在/source/_data下新建link.yml

    2. 添加内容

图库

  1. 图库是普通页面，使用 hexo new page xxxx 即可
  2. 使用标签外挂 galleryGroup

子页面

  1. 子页面也是普通页面，使用 hexo new page xxxx 即可
  2. 使用标签外挂 gallery

页面配置

配置文件有2种：

  • 主配置文件_config.yml，位于根目录下，为hexo博客的配置文件
  • 主题配置文件，格式为 _config.[主题名].yml（如_config.butterfly.yml），在hexo中修改主题后会生成，也可以自己新建，demo位于/node_modules/对应主题包文件下

网站资料

在hexo主配置文件_config.yml中修改

导航菜单

  • 在主题配置文件_config.butterfly.yml中修改

格式必须为/xxx/ || [图标名]，前面的导航文字可自行修改

顶部图片

如不想显示顶部图片，可直接配置disable_top_img: true

  • 可配置页面
配置 解释
index_img 主页的top_img
default_top_img 默认的top_img，页面的top_img未配置时显示
archive_img 归档页面的top_img
tag_img tag子页面的默认top_img
tag_per_img tag子页面的top_img，可配置每个tag的top_img
category_img category子页面的默认top_img
category_per_img category子页面的top_img，可配置每个category的top_img

其他页面（/tags、/categories、自建页面、文章页）的top_img在font-matter中配置

  • top_img配置内容
配置的内容 效果
留空 默认的top_img
img链接 显示配置的图片
颜色 对应颜色（HEX值、rgb值、颜色单词、渐变色）
transparent 透明
false 不显示

    1. 添加到Inject配置

    2. 使用图标

主页文章节选

只支持自动节选和文章页description

ButterFly提供四种模式：

  1. description：只显示description
  2. both：优先显示description，没有配置则显示自动节选
  3. auto_excerpt：只显示自动节选
  4. false：不限时文章内容
  • 修改主题配置文件_config.butterfly.yml

文章封面

文章的font-matter中使用cover属性进行配置。

若不配置，这显示默认的cover；若不想显示可以设置为false

  • 修改主题配置文件_config.butterfly.yml

LeanCloud设置（数据库）

  1. 登录/注册LeanCloud 国际版
  2. 进入控制台，创建应用（开发版）
  3. 进入应用，选择 “设置 - 应用凭证”， 获取到 APP ID, APP Key和Master Key

Vercel设置（服务端）

  1. 进入 Vercel 进行Serve 端部署
  2. 登陆（建议GitHub）后创建项目（Create a Team 可以跳过）
  3. 经过1-2分钟的部署后会出现Congratulations!的界面，点击Go to Dashboard
  4. 进入“ Setting - Environment Variables”，添加三个环境变量LEAN_ID, LEAN_KEY, LEAN_MASTER_KEY分别对应LeanCloud 的 APP ID, APP Key和Master Key
  5. 配置完成后点击 顶部Deployments，在项目右侧更多中选择 Redeploy重新部署使配置生效
  6. 等待1-2分钟后部署完成，点击Visit即可进入评论服务端页面。此地址即为自己的服务端地址

仓库统计

  1. 下载 npm i github-calendar --save

  2. 配置主配置文件_config.yml

    • butterfly主题下只要修改user就可以生效，位置在主页；如要显示在其他页面需自行配置

    • api为公用的api，请不要滥用。如要搭建自用api，请参考python_github_calendar_api或python_gitee_calendar_api

    • 其他主题的github-calendar的版本见 Issues · Zfour/hexo-github-calendar · GitHub

  3. 配置项含义

    • enable：是否启用
    • enable_page：应用页面
    • user：github或gitee用户名
    • layout：
    • githubcalendar_html：html 模板字段
    • pc_minheight：PC下网页显示的图表高度
    • mobile_minheight: 0px：手机下网页显示的图表高度
    • color：主题配色
    • api：查询仓库信息的api
    • calendar_js：jsd 加速的 js，将 github calendar 挂载入容器中
    • plus_style：可自定义 style

电子时钟

  1. 安装 npm i hexo-electric-clock --save

  2. 配置主配置文件_config.yml

固定链接

hexo的固定链接可以通过修改主配置文件_config.yml中的permalink进行配置，一般默认配置为:year/:month/:day/:title/，具体的配置请参考 永久链接（Permalinks） | Hexo

但带日期的url在我看来总觉得怪怪的，而且大部分的title都是中文，在url中还是尽可能减少中文吧，所以我改用了hexo-abbrlink来生成固定链接。

githu 主页：GitHub - rozbo/hexo-abbrlink: create one and only link for every post for hexo

  1. 安装 npm install hexo-abbrlink --save

  2. 修改主配置文件_config.yml

    其中，

    • alg：配置算法（crc16 和 crc32）
    • rep：配置进制（dec - 十进制，hex - 十六进制）

    crc16 + dec效果为：http://localhost:4000/posts/36266/

  3. hexo clean / g / d 三兄弟 （未进行clean会导致早期的文章url变成undefined）

注意：应用之后文章之前的阅读量等信息会被重置，虽说从建站到应用abbrlink已经过去了近四个月，但我这小破站也不在乎这点，毕竟只是自己做着玩，谁会在意阅读量是9还是1呢
